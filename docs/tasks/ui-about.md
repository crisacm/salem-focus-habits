# The About screen on the shared UI (KMP step 7, PR 5a)

## Objetivo
Move the About screen to `salem-ui` so Android and iOS share it, and show it on iOS (menu item About and Help).

## Por qué
iOS only logs `showAboutScreen`/`showFAQScreen`. The last slice of step 7 moves About, Intro and Settings in three stacked PRs: 5a About plus the common base (links, translators, top bar, screen navigation, open-URL hook), 5b Intro and its first launch on iOS, 5c Settings.

## Alcance
- In: `salem-ui` `ui.about` (`AboutContent`, `AboutRoute`, `AboutCredits`, `DeveloperCountdown`), `SalemLinks` (URLs as Kotlin constants, checked against `constants.xml` by a test), `Translators` (generated by `updateTranslators` from the two CSV files), `SalemTopAppBar`, `ScreenNavigation`, the intro icons as shared drawables (through `syncSharedStrings`), the iOS layer and the `UIApplication.openURL` hook. Android: `AboutActivity` as host; `AboutContent`, `AboutScreen`, `AboutCredits`, `DeveloperCountdown`, `about_translators.xml` are deleted.
- Out: Intro (5b), Settings (5c).
- Decisions (user): odd-full, 3 stacked PRs, URLs as Kotlin constants, translators generated as Kotlin, an open-URL hook, TDD where there is logic, no emulator/simulator without asking.

## Exploración
Haiku `explorer` brief: About was pure Compose except the translators block (`AndroidView` over a generated XML layout), `R.*` ids, and `AboutScreen` (Intents). URLs live in `constants.xml`, which is not synced to Compose resources. The iOS pattern is `DetailNavigation` plus a route composed above the list.

## Incertidumbre
- Two sources for the URLs (`constants.xml` for the Android intents and widgets, `SalemLinks` for the shared screens): a desktop test compares them.
- The developer unlock now shows a snackbar instead of a toast on Android. Not seen on a device.
