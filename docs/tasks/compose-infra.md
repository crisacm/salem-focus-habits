# Jetpack Compose on Android: infrastructure and About pilot (KMP step 6a/6b)

## Objetivo
Add Jetpack Compose to `salem-android`, a `SalemTheme` that maps the core `Theme`, and migrate the About screen as the first Compose screen.

## Por qué
Step 6 of `.specs/migration-kmp.md`. The rest of the screens will move slice by slice; this task proves the toolchain, the theme and the testing approach on the smallest screen.

## Alcance
- In: Compose plugin and dependencies (version catalog only), `SalemTheme`, About screen in Compose (activity class name kept), About strings moved to `strings.xml`, JVM tests for theme mapping and the developer counter, a compile-only `createComposeRule` smoke test, CHANGELOG, PENDING and AGENTS.md.
- Out: other screens (roadmap: Settings, Intro, dialogs, list, detail, edit, charts), a theme selector in Compose, translations of new strings, widgets (stay RemoteViews).
- Decisions (user): scope 6a+6b; theme from core `Theme` (Light/Dark/PureBlack); `ui-test-junit4` in androidTest (compile only) plus JVM tests, no screenshot library; odd-full.

## Exploración
- No Compose anywhere: no plugin, BOM or `buildFeatures.compose`. Plugins and libraries are declared only in `gradle/libs.versions.toml`; AGP 8.9.2, Kotlin 2.3.20 (Compose compiler plugin `org.jetbrains.kotlin.plugin.compose` 2.3.20 exists), BOM 2026.09.00 and activity-compose are on Google Maven.
- Theme: `core/ui/views/Themes.kt` has `Theme` (appBackground, cardBackground, headerBackground, text contrast colors, toolbar, statusBar, 20-colour palette), `LightTheme`, `DarkTheme`, `PureBlackTheme : DarkTheme`. XML styles/`colors.xml`/`PaletteUtils` duplicate and slightly diverge from it. `ThemeSwitcher.apply()` chooses from prefs; `AndroidThemeSwitcher` also applies the XML theme and sets `currentTheme`.
- About: `AboutActivity` (AppCompatActivity, takes `intentFactory` and `preferences` from `HabitsApplication.component`) → `AboutScreen` (link methods via `IntentFactory`, 5-tap `developerCountdown` that sets `prefs.isDeveloper`) → `AboutView` + `about.xml` + `about_translators.xml` (binding `AboutBinding`). Entry points: list menu and `preferences.xml` (by class name), `SavedStateTest` starts `AboutActivity` by class. Hardcoded English texts in the layouts (Loop credit, developers, translators, Salem author).
- Tests: `AboutTest` checks "Loop Habit Tracker", "Rate this app on Google Play", "Developers", "Translators"; `LinksTest` is `@Ignore`d. No Android framework in JVM tests (Mokkery, no Robolectric); `AboutScreen` is not JVM-testable today.

## Incertidumbre
- Compose BOM compatibility with AGP 8.9.2: BOM 2026.09.00 (Compose 1.12) requires AGP 9.1 and compileSdk 37; 2026.02.00 (Compose 1.10.3) builds. `activity-compose` 1.13.0 pulls an activity version with a non-null `onNewIntent(Intent)`, so `ListHabitsActivity` was adjusted.
- `about_translators.xml` is generated by `updateTranslators` (also a dependency of `compileLint`), so it was kept and embedded in Compose with `AndroidView`. `Espresso` view matchers cannot see Compose text, so `AboutTest` uses a Compose rule.
- `verifyDisplaysText` matching (substring or exact) decides how the About texts must stay: check before changing texts.
